= Zero Trust Workload Identity Workshop

A focused hands-on workshop covering Zero Trust database authentication using SPIFFE/SPIRE and the Zero Trust Workload Identity Manager (ZTWIM) on OpenShift.

== Workshop Overview

This workshop demonstrates how to eliminate static database credentials by implementing cryptographic workload identity with SPIFFE (Secure Production Identity Framework for Everyone) and SPIRE on OpenShift. Learn how to establish mutual TLS (mTLS) database connections using short-lived X.509 certificates instead of passwords.

**Duration:** 45-60 minutes total

=== Workshop Content

* *link:content/modules/ROOT/pages/index.adoc[Setup & Overview]* (10-15 min) - Lab access, ZTWIM verification, zero trust concepts, SPIFFE/SPIRE fundamentals
* *link:content/modules/ROOT/pages/17-ztwim.adoc[Zero-Trust Workload Identity]* (20-30 min) - Configure ZTWIM/SPIRE, deploy PostgreSQL with certificate-based auth, inspect SPIFFE certificates, establish mTLS connections, verify access control
* *link:content/modules/ROOT/pages/99-conclusion.adoc[Wrap Up]* (5 min) - Summary, key takeaways, next steps

=== What You'll Learn

* **Eliminate static credentials** - Replace database passwords with cryptographic identity
* **Configure SPIFFE/SPIRE** - Set up the Zero Trust Workload Identity Manager
* **Deploy PostgreSQL with mTLS** - Configure certificate-based authentication
* **Inspect certificates** - Examine short-lived X.509 certificates and SPIFFE IDs
* **Establish mTLS connections** - Connect to databases using certificates instead of passwords
* **Verify zero trust enforcement** - Confirm unauthorized workloads are rejected
* **Understand automatic rotation** - See how certificates renew without downtime

=== Zero Trust Principles

This workshop puts these zero trust principles into practice:

1. **Never trust, always verify** - Cryptographically verify every connection
2. **Assume breach** - Minimize blast radius with short-lived credentials
3. **Least privilege** - Each workload gets only the identity it needs
4. **Verify explicitly** - Authenticate based on what the workload is, not where it runs

== Local Development

=== Using local-build scripts (Recommended)

From the repo root, build and preview the workshop with Podman:

[source,sh]
----
./local-build/up.sh
----

Open http://localhost:8080/index.html in your browser.

Other commands:

[cols="1,2"]
|===
| `./local-build/build.sh` | Generate the static site into `./www/` using `site.yml`
| `./local-build/serve.sh` | Serve `./www/` with httpd in Podman (port 8080)
| `./local-build/stop.sh` | Stop the local httpd container
| `./local-build/reset.sh` | Stop, rebuild, and serve again
| `./local-build/status.sh` | Show container status
|===

Optional environment variables (see `local-build/_common.sh`):

* `SHOWROOM_PORT` — host port (default `8080`)
* `SHOWROOM_PULL=1` — pull the httpd image before starting
* `SHOWROOM_SITE_YML` — alternate Antora playbook (default `site.yml`)

=== Using Antora CLI directly

[source,sh]
----
npm i -g @antora/cli@3.1 @antora/site-generator@3.1
antora generate site.yml --stacktrace
----

Output is generated in `./www/`. Serve with `./local-build/serve.sh` or any static file server.
